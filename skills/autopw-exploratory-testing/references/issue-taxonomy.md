# 问题分类标准

根据实际影响、受影响用户、绕行方案、数据风险和安全后果分级。静态发现使用“潜在严重级别”，不要计入已验证问题数量。

## 严重级别

- **🔴 严重（Critical）：** 核心功能整体不可用；发生不可逆数据损失/错误资金操作；敏感数据可被大范围未授权访问；或安全漏洞已有可利用链和现场证据。
- **🟠 高（High）：** 关键流程不可用或明显不安全，且没有合理绕行方案；或可造成重要数据/权限影响。
- **🟡 中（Medium）：** 功能、状态或反馈明显错误，但存在可行绕行方案，或影响次要流程。
- **🔵 低（Low）：** 影响有限的视觉、文案、可访问性、Console 噪声或易用性问题。

不要因为源码中存在可疑模式就直接定为 Critical。Critical 安全问题应有可达性和利用效果证据；未现场复现时放入静态发现。

## 类别

- **功能：** 行为违反用户流程、业务规则或 API 契约。
- **安全与隐私：** 未授权访问、注入、敏感信息泄漏、凭据问题或隐私失败。
- **视觉：** 布局、遮挡、裁切、响应式或资源显示问题。
- **可访问性：** 键盘、焦点、语义、可访问名称、对比度或辅助技术障碍。
- **Console/网络：** 未处理页面异常、失败请求或有实际影响的浏览器错误。
- **UX：** 状态误导、反馈缺失、恢复困难或交互含义不清。
- **内容：** 文案、媒体或信息错误、缺失、不一致。

同一根因产生多个表现时，优先采用最能体现用户影响的主类别，把其他表现写进证据，避免重复计数。
